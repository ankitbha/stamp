# Task 10 Execution Plan — Controlled Experiment Suite

Date: 2026-07-20
Spec: `ROADMAP_STAMP_NEW.md` "Task 10: Controlled experiment suite" (lines 1721-1845).

## Objective

Implement the paper's Experiment 1–10 controlled matrix on a single shared New
Delhi base platform, plus the observed-New-Delhi study mode. Each experiment
varies exactly one controlled axis and reports BOTH attribution accuracy and
identifiability diagnostics. Task 11 (later) turns the saved summaries into the
paper's result tables.

Gates S1–S7 all pass, so the primitives are trusted; Task 10 is orchestration on
top of `model/iasa/*` — the gate functions in `scripts/run_iasa_sanity.py` are
working reference pipelines for every experiment.

## Shared base platform (`platform.py`)

One platform, reused by every experiment so wind/source/background/geometry
comparisons use identical source, temporal-basis, sensor, observation-mask, and
background columns on both sides.

- Grid: reduced default `Nx=Ny=20`, `T=24` (config-overridable) so a full sweep
  runs in minutes on an L40S. Real inventory maps via
  `sim.pol_sources.load_pol_source_inventory` cropped+downsampled to the platform
  grid; four proxy source groups (traffic/brick_kilns/industries/population_density
  — the declared inventory).
- Sensors: regulatory geometry from `data.pol_weather.load_new_delhi_wind_data`
  station lon/lat mapped to grid cells; plus alternate layouts (seeded random,
  downwind-focused) for Experiment 4.
- Temporal basis: declared proxy bases (`TemporalBasis`), e.g. impulse+constant or
  the diurnal/block bases used in the fit gate; `build_default_activity_profile`
  supplies synthetic ground-truth coefficients for controlled runs.
- Winds: `constant_direction`, `single_direction_synthetic`, `diurnal_synthetic`,
  `ar1_synthetic`, `multi_direction_synthetic`, and real imputed
  (`real_new_delhi_wind_sequence` / `gridded_new_delhi_wind_field`).
- Background: primary rank-4 basis (constant, centered linear, first daily sin/cos)
  declared in config; redundant + source-like stress bases for Experiment 3.
- Everything a fit consumes (primary `Q`, lag rule, fixed-zero mask, inventory
  version) is DECLARED in the config and stamped into provenance — never selected
  from `Y` or fit quality.

## The ten experiments (`experiments.py`)

Each `run_expNN(platform, cfg, seed) -> dict` returns a JSON-able result with an
`accuracy` block and a `diagnostics` block (+ experiment-specific fields), plus
arrays destined for `arrays.npz`. Reference gate noted per experiment.

1. **E1 conditioning predicts recovery** — sweep Gaussian noise
   {0,1,5,10,20}% of max clean signal × source geometry; report coeff + activity
   error vs `sigma_J`, numerical/effective rank, condition number, visibility.
   (ref: fit + diagnostics gates)
2. **E2 coherent sources → grouped reporting** — shift a copy of one inventory map
   by decreasing spatial offset (coherence→1); compare individual-source error vs
   summed activity/sensor-contribution error per recommended connected component;
   retain triggering source–basis pair. (ref: merge gate)
3. **E3 background helps or hurts** — none / primary rank-4 / redundant-span /
   source-like stress bases; audit visibility + removed/raw absorption ratio; all
   declared before fitting. (ref: projection gate)
4. **E4 wind diversity & geometry** — matched columns under constant, single,
   diurnal, AR(1), multi-directional, real winds × sensor layouts
   {regulatory, seeded random, downwind}; plus historical & simulated wind-window
   ensembles → 5/50/95th `sigma_J`, rank/weakness/ambiguity probabilities,
   conservative-component frequencies via `summarize_wind_ensemble`. (ref:
   diagnostics gate + wind_field gate)
5. **E5 transport error amplified by ill-conditioning** — (a) parametric wind
   speed/direction/dispersion perturbations within the puff family (transport
   ensemble); (b) STRUCTURAL: generate `Y` with `edge_hold_pde.py` (upwind
   advection, 5-pt Laplacian, two-stage Heun, k=3e-4, edge-hold) while fitting the
   open-boundary puff response. Report operator error norm, coeff/activity error,
   residual, singular spectrum; structural case drives the adequacy test + its
   rejection rate. Generator labeled `edge_hold_pde`, never silently substituted.
6. **E6 inventory error changes target** — perturb inventory location/scale/category/
   version with transport fixed; each alt inventory is a separate robustness
   scenario via `aggregate_inventory_scenarios`, never pooled with E5, never a CI.
7. **E7 lag-window sensitivity** — candidate grid from travel/residence times; for
   adjacent candidates `||H(L+δ)-H(L)||_F / max(||H(L+δ)||_F, eps)`, select smallest
   `L ≤ τ_L=1e-3`; report rank/conditioning/report-component stability; row count
   fixed; coefficients never used for selection. (ref: response builder at varying
   `lag_window_steps`)
8. **E8 missing-source adequacy** — omit (a) a residual-visible source outside
   `span([H_lag,Q])` and (b) an aligned source inside that span (required negative
   control); refitted parametric bootstrap (declared Gaussian cov, 1000 reps,
   α=0.05) for calibration + power. (ref: fit gate cases 7–8 + calibration gate)
9. **E9 temporal-basis recovery** — reconstruct traffic diurnal / brick-kiln
   intermittent / industry day-night / mixed coefficients at increasing noise,
   separating coeff error from reconstructed activity-trajectory error. (ref: fit
   gate case 9)
10. **E10 footprints & spatial attribution** — controlled: Task 9B footprints
    localize responsible upwind cells + per-sensor contributions sum to fitted
    sensor signal; observed: per-monitor fitted group contributions + origin cells
    aggregated to identifiable report groups. (ref: footprints gate)

Hypothesis map (E1→H1 … E6→H5b) recorded as provenance only; expected directions
are NOT encoded as conclusions.

**Observed New Delhi mode** — real PM2.5 + mask + gridded imputed wind + named
normalized inventories + declared proxy bases; NO ground-truth coefficients;
reports residuals, geometry, uncertainty, weak/ambiguous coeffs, normalized proxy
contributions, recommended report groups. Never assigned synthetic recovery metrics.

## Runner + provenance (`run_experiment.py`, `runio.py`)

- CLI `--config configs/expNN.json --seed N [--out runs/] [--device cpu|cuda]`.
  Non-interactive, writes and exits clean; JSON to stdout is a clean channel
  (progress → stderr) so sbatch can parse it.
- Writes `runs/<exp>_seed<N>/`: `config.resolved.json` (config + seed + git SHA +
  device + dtype + torch/cuda versions via `runtime_provenance`), `result.json`
  (accuracy + diagnostics summaries), `arrays.npz` (H_lag, H_tilde, masks, c_hat,
  footprints, singular spectra, adequacy arrays).
- `summarize_results.py` scans `runs/`, emits `summaries/expNN_summary.csv` +
  a combined `summaries/all_experiments.json` (small, committed) for Task 11.

## GPU execution

All torch runs on a SLURM L40S node via sbatch (never login node):
`--account=torch_pr_633_general --partition=l40s_public --gres=gpu:1
--cpus-per-task=4 --mem=16G`, container + overlay, `OMP_NUM_THREADS=1`,
non-blocking background poller. A `--gate experiments` sub-gate is added to
`run_iasa_sanity.py` running a fast reduced-scale sweep of all ten + observed for
CI-style verification.

## Tests (`tests/test_iasa_experiments.py`)

Reduced-scale (tiny grid/T/reps) unit tests: each experiment returns the required
`accuracy`+`diagnostics` schema; runner round-trip (config→run→reload) reproduces
identical results under a fixed seed; provenance carries Q/lag/mask/inventory
version + git/device/dtype; type-separation guard (E5 transport vs E6 inventory)
holds; E5 structural generator is labeled `edge_hold_pde`; observed mode carries
no recovery metrics.
