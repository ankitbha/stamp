# Task 9B Execution Plan: Per-sensor footprints and spatial attribution

## Objective

Resolve each monitor's fitted signal into contributing source groups and spatial
cells of origin, per paper `5.theory.tex` subsec:per_sensor_footprints. Two
products: (1) the exact per-sensor contribution decomposition (projected and
raw), and (2) nonnegative sensor footprint fields over source cells. Report
per-sensor shares only at the globally identifiable resolution (aggregate to
Task 9 report groups), and record the inheritance guarantee that a single sensor
is never more identifiable than the pooled network.

## Context (verified against paper/5.theory.tex subsec:per_sensor_footprints)

- Per-sensor decomposition (eq. per_sensor_decomposition): because the response
  is linear in `c`, `y_tilde_{s,t} = sum_{k,b} H_tilde_{(s,t),(k,b)} c_hat_{kb}`,
  so `Y_hat^{(s)}_k = sum_t sum_b H_{(s,t),(k,b)} c_hat_{kb}`. Projected form
  (`H_tilde`) isolates the identifiable part; unprojected (`H_lag`) gives the raw
  fitted contribution before background removal. This is pure linear algebra on
  the already-built matrices -- no rebuild.
- Sensor footprint (eq. sensor_footprint):
  `F_{s,t}(i) = sum_{ell in L_t} [O G^partial_{t,t-ell}(w_hat)]_{s,i} >= 0`,
  `F_s(i) = sum_t F_{s,t}(i)`, a nonnegative field over source cells. Weighting by
  `phi_b(t-ell)`, the inventory map `s_k`, and `c_hat_{kb}` resolves each group's
  fitted contribution by cell of origin. "This is the puff response of
  Section plume_response read backward from the sensor and requires no new
  transport operator." -> obtain per-cell transport by re-running the Task 5
  builder with one-hot single-cell sources (each cell is a delta); its response
  column is exactly the pullback `[O G]_{s,i}` under the given basis.
- Identifiability inherited (eq. footprint_inheritance): for the per-sensor row
  submatrix `H_tilde^{(s)}`, `H_tilde^{(s)T} H_tilde^{(s)} <= H_tilde^T H_tilde`,
  so `sigma_J(H_tilde^{(s)}) <= sigma_J(H_tilde)` and
  `rank(H_tilde^{(s)}) <= rank(H_tilde)`.

Verified interfaces: rows are time-major sensor blocks (`row_index` entries carry
`time_index, sensor_index, sensor_id`). `ProjectionResult` provides
`H_tilde, H_removed (H_lag=H_tilde+H_removed), row_index, column_index`. `FitResult`
provides `c_hat` (full), `fitted_sensor_vector = H_tilde c`, `source_basis_metadata`.
Task 9 `MergeResult.report_components` provide source-index groups.

## Design -- new `model/iasa/footprints.py`

### Exact per-sensor decomposition (no rebuild)
`decompose_per_sensor(H_tilde, H_lag, c_hat, row_index, column_index, *,
groups=None) -> dict`:
- For each sensor (`sensor_index`), gather its rows (all times). Per source `k`:
  `Y_proj^{(s)}_k = sum_{r in rows(s)} sum_{b} H_tilde[r,(k,b)] c_hat[(k,b)]` and
  the raw form on `H_lag`. Aggregate to `groups` when given.
- Guarantees by construction: `sum_k Y_proj^{(s)}_k == sum_{r in rows(s)}
  (H_tilde c)[r]` (the fitted per-sensor signal), so contributions sum to the
  fitted sensor-time signal.

### Sensor footprints (reuse Task 5 builder, one-hot cell sources)
`compute_sensor_footprints(source_maps, source_names, basis, observer, wind, *,
fit, projection, response_config, dispersion_config, groups=None,
cell_threshold=1e-6, max_cells=4096) -> FootprintResult`:
- Active cells = union over fitted sources of `{(ix,iy): map_k(ix,iy) >
  cell_threshold}`; cap at `max_cells` (log/raise if exceeded).
- Build ONE per-cell response with `build_lagged_response_matrix` using one-hot
  single-cell sources and the SAME `basis, observer, wind, configs`. Its column
  `(cell_j, b)` row `(s,t)` is the per-cell transport pullback under basis `b`.
- Geometric footprint `F_s(i) = sum_b sum_{t} H_cell[(s,t),(cell_i,b)]` -- the
  nonnegative unit-source transport pullback aggregated over the basis
  (inventory/coefficient-free), localizing upwind origins.
- Fitted per-(sensor, group, cell) footprint:
  `sum_{k in g} map_k(i) sum_b c_hat_{kb} sum_t H_cell[(s,t),(cell_i,b)]`,
  nonnegative, and summing over cells `i` recovers the raw per-sensor group
  contribution (consistency by construction).

### Inheritance guarantee
`per_sensor_identifiability(projection, sensor_index, *, config=None,
pooled=None) -> dict`: run `diagnose_identifiability` on the per-sensor row
submatrix `H_tilde^{(s)}` and the pooled `H_tilde`; report
`sigma_J^{(s)} <= sigma_J` and `rank^{(s)} <= rank` with an `inherited` flag.

### Result dataclass `FootprintResult` (torch/numpy at boundaries)
`sensor_ids`, `per_sensor_source_contribution_{projected,raw}`,
`per_sensor_group_contribution_{projected,raw}` (if groups),
`geometric_footprint[sensor -> [Nx,Ny]]`, `fitted_footprint[sensor -> {group ->
[Nx,Ny]}]`, `grid_shape`, `active_cells`, `metadata`. `to_json_summary()`.

## Sanity Gate (`scripts/run_iasa_sanity.py --gate footprints`)
Controlled scenario: a known interior source under a fixed wind, sensors placed
so the source is upwind of one sensor. Fit, then verify:
- Per-sensor contributions (projected) sum to the fitted per-sensor signal within
  tolerance.
- Footprints are nonnegative and the geometric footprint of the downwind sensor
  peaks at/near the true source cell (localizes the upwind origin).
- Fitted per-group footprints sum over cells to the raw per-sensor group
  contributions.
- Per-sensor `sigma_J^{(s)} <= sigma_J` (pooled) and `rank^{(s)} <= rank` for
  every sensor (inheritance).
Wire `--gate footprints` into the CLI and `--gate all`.

Roadmap Task 9B: per-sensor contributions sum to the fitted sensor-time signal;
footprints nonnegative and localize known upwind origins; per-sensor shares

(inheritance). Reuse Task 5 operator; no new transport; torch compute with numpy

## Risks
- Row selection must match the time-major sensor-block layout; a wrong mapping
  scrambles per-sensor sums.
- The one-hot cell build must use the identical basis/observer/wind/configs as
  the fitted response, or footprints will not sum to the fit.
- Footprint nonnegativity depends on the transport pullback being nonnegative
  (open-boundary puff kernel deposits nonnegative mass); assert it.
- Cap `max_cells` so dense maps do not trigger an enormous per-cell build; log
  when active cells are thresholded.
