# Task 6A Execution Plan: PyTorch computational backend consolidation

## Objective

Make PyTorch the sole computational backend for the IASA numeric core
(response, background, projection, and activity compute helpers) before Task 7.
Pandas/NumPy remain only at CSV/NPZ ingestion and serialization boundaries.
Expose explicit `device`/`dtype`, attach runtime + data provenance to artifacts,
add `ensemble_kind` tagging, and keep the existing public row/column ordering,
boundary semantics, and metadata schema. Gates S1/S2 and all IASA tests must
still pass, without SciPy in any compute path.

## Context / current state (verified)

- `model/iasa/{response,background,projection,activity,wind}.py` are all NumPy.
- Container runtime (overlay + `/ext3/env.sh`): `torch 2.6.0+cu118`, `numpy
  1.26.4`, `scipy 1.16.2` present; `torch.cuda.is_available()` is False on the
  login node (CUDA parity leg runs on a SLURM GPU allocation).
- `ResponseMatrixResult.H_lag`/`baseline`, `BackgroundBasisResult.Q`,
  `ProjectionResult.{H_tilde,Y_tilde,H_removed,Y_removed,Q,U_r}` currently hold
  `np.ndarray`. Task 6A requires these numeric arrays to be `torch.Tensor` on the
  requested device until an explicit serialization boundary.

## Design

### New: `model/iasa/backend.py`

- `DEFAULT_DEVICE = "cpu"`, `INVERSE_DTYPE = torch.float64`,
  `RESPONSE_DTYPE = torch.float32`.
- `resolve_device(device) -> torch.device` and `resolve_dtype(dtype)`.
- `to_numpy(t) -> np.ndarray` = `t.detach().cpu().numpy()` (the only sanctioned
  tensor->NumPy boundary).
- `as_tensor(data, *, device, dtype)` for ingestion-boundary conversion.
- `runtime_provenance(device, dtype) -> dict` with `device`, `dtype`,
  `torch_version`, `cuda_version`, `cuda_available`.
- `tensor_hash(t) -> str`: stable sha256 over contiguous CPU float64 bytes, used
  for inventory/wind/parent-artifact provenance hashes.
- `ENSEMBLE_KINDS = {"transport", "inventory"}` and a `validate_ensemble_kind`.

### `response.py`

- Add to `ResponseConfig`: `device: str = "cpu"`, `response_dtype: str =
  "float32"`, `ensemble_kind: str = "transport"`.
- Port to torch on the resolved device/dtype: source-map cell math, puff
  advection (`_advect` uses 2-vectors of torch), orientation, the anisotropic
  Gaussian evaluated at sensors (`_gaussian_at_points`), retained-mass grid
  quadrature (`_retained_kernel_mass`), and the `H`/`baseline` accumulation.
- `ResponseMatrixResult.H_lag`/`baseline` become `torch.Tensor` on device.
- Metadata additions: `device`, `response_dtype`, `torch_version`,
  `cuda_version`, `cuda_available`, `ensemble_kind`, `inventory_hash`
  (hash of source maps + names), `wind_realization_hash`, `dispersion_settings`
  (already via `dispersion_config`), `observation_mask` (None at this stage; the
  full unmasked builder), `parent_artifact_hashes` (empty list). Keep all
  existing keys and semantics (`.tolist()` remains the serialization boundary).
- Numerics preserved: same substep advection, same `1/25` 5x5 sub-cell
  quadrature, same clip `clip(raw_retained_fraction, 0, 1)`, same source-major /
  basis-minor column order and time-major row order.

### `background.py`

- Add `device`/`dtype` (default `float64`) to `BackgroundBasisConfig`.
- Timestamp/day parsing stays NumPy (ingestion boundary); assemble column values
  as torch tensors, stack `Q` as a torch tensor, compute effective rank with
  `torch.linalg.svdvals`. `BackgroundBasisResult.Q` becomes a `torch.Tensor`.
- Metadata unchanged in schema; add `device`, `dtype`, `torch_version`.

### `projection.py`

- Torch throughout at `float64`. `fit_background_projector` uses
  `torch.linalg.svd`; `project` applies `X - U_r @ (U_r.T @ X)` in torch on the
  projector device. Prefix-rank column classification uses `torch.linalg.svdvals`.
- `_norm_ratios` and orthogonality/idempotence residuals use torch norms.
- Result tensors (`H_tilde`, `Y_tilde`, `H_removed`, `Y_removed`, `Q`, `U_r`)
  stay on device. Metadata scalar summaries via `float(...)` at the boundary.
- Provenance additions: `device`, `dtype`, `torch_version`, `cuda_version`,
  parent `background_basis` hash, and `ensemble_kind` passthrough when present.

### `activity.py`

- Port `build_theta_from_temporal_basis` (einsum tb,kb->tk) and
  `combine_inventory_sources` (einsum) and `validate_activity_theta` to torch.
  Return values may stay NumPy at the profile boundary to avoid churn in Task 3A
  consumers, but the reductions run in torch. Timestamp/hour derivation stays
  NumPy (ingestion).

### `wind.py`

- Unchanged: CSV/NPZ ingestion boundary producing `vx/vy` arrays.
  `CityWindSampler` converts to torch tensors internally for advection.

### Sanity runner (`scripts/run_iasa_sanity.py`)

- S1/S2 gates: convert result tensors to NumPy via `to_numpy` at the point where
  NumPy-only checks/`np.testing` run (treat NumPy as the runner's serialization
  boundary). All existing thresholds unchanged.
- Add `--gate parity`: build the S1 response and S2 projection on CPU, and, when
  `torch.cuda.is_available()`, rebuild on CUDA and compare with *relative*
  tolerances. Response parity compares the independently built float32 responses
  (relative tol `1e-4`). Projection parity is isolated by projecting the SAME
  CPU-built response on each device (so only the float64 background-SVD/projection
  backend is compared, not the upstream float32 response divergence); relative tol
  `1e-6` (observed ~1e-15). When CUDA is unavailable, record
  `cuda_available=false`, `status="cpu_only"` (not a failure). Emit a device/dtype
  parity summary.
- Extend `--gate` choices and `all` to include `parity`.

### Tests

- Update `tests/test_iasa_{response,background,projection}.py` to accept
  `torch.Tensor` result fields, converting with `.detach().cpu().numpy()` where a
  NumPy op or `np.testing.assert_allclose` requires an array. Assert result
  fields are `torch.Tensor` on the requested device and that new provenance keys
  (`device`, `dtype`, `ensemble_kind`, `torch_version`) are present.
- Add a small `tests/test_iasa_backend.py` for `to_numpy`, device/dtype
  resolution, `ensemble_kind` validation, and hash stability.

## Steps

1. Add `model/iasa/backend.py`.
2. Port `response.py`; keep numerics identical; add device/dtype/provenance.
3. Port `background.py` and `projection.py`.
4. Port `activity.py` compute reductions.
5. Update `scripts/run_iasa_sanity.py` (S1/S2 conversions + new parity gate).
6. Update tests; add `test_iasa_backend.py`.
7. Update `model/iasa/__init__.py` exports if new symbols are public.
8. Run in container (CPU): `--gate response`, `--gate projection`,
   `--gate parity`, `--gate all`, and `python -m pytest tests/ -q`. Fix drift.
9. Record CPU parity as the pre-consolidation match (existing gate thresholds);
   note CUDA parity is validated on a SLURM GPU node.
10. Strikethrough Task 6A in `ROADMAP_STAMP_NEW.md`.

## Acceptance mapping

- CPU torch matches pre-consolidation -> unchanged S1/S2 thresholds + tests pass.
- CPU/CUDA agree -> `--gate parity` (GPU leg on SLURM).
- Outputs remain on device until serialization -> result fields are tensors;
  NumPy only via `to_numpy` at boundaries; tests assert tensor+device.
- Gates S1/S2 pass without SciPy -> no `scipy` import in any `model/iasa` module
  or compute path (grep clean).

## Risks / mitigations

- Consumer breakage from tensor results: CPU tensors satisfy NumPy's `__array__`,
  so most `np.asarray`/ufunc/`np.testing` calls keep working; explicit
  torch@numpy mixes are converted at use sites. Run tests to catch residual drift.
- float32 response accumulation order differences vs NumPy: keep the same loop
  and reduction structure; gate tolerances already allow `1e-5`-scale slack.
- No GPU on login node: parity GPU leg is deferred to SLURM and reported as
  `cpu_only` locally rather than failing.
