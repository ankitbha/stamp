## Objective

Train the vendored coordinate-query `FieldFormerCoordinateQuery(out_dim=2)` to
impute the 2-vector transport wind field `(Ux, Vy)` for New Delhi, producing the
checkpoint that activates `FieldFormerCoordinateQueryImputer` (Task 9A). Training
and query must use identical conventions (min-max `xy`->[0,1], `t/(T-1)`, s-major
tuples `lin=s*T+k`, `k_neighbors`/`time_radius`) or the learned attention is
queried off-distribution.

## Data and supervision

- Load with `data.pol_weather.load_new_delhi_wind_data(data_csv, locations_csv,
  start, end)` -> `observed_vectors [S,T,2]`, `vector_mask [S,T,2]` (use
  `[...,0]`), `sensors_xy [S,2]` (lon,lat), `station_ids`, `timestamps`.
- Map stations lon/lat -> grid coords `(ix, iy)` EXACTLY as
  `gridded_new_delhi_wind_field` (min-max lon/lat -> `[0, nx-1]`/`[0, ny-1]`).
- Supervision = sparse observed tuples `(x, y, t) -> (Ux, Vy)` for `mask[s,k]`.
  Vectors already come from WD/WS via `transport_vectors_from_wd_ws` inside the
  loader (paper eq. wind_direction_conversion).
- Normalization mirrors the adapter (`FieldFormerCoordinateQueryImputer`):
  min-max `xy` to `[0,1]` from the station extent, `t = k/(T-1)`. Record the
  resulting `domain_bounds` (grid-coord station min/max) in provenance so the
  adapter can be built with the identical normalization.
- Tuple layout: `obs_coords [S*T, 3]` and `obs_vals [S*T, 2]` in s-major order,
  `lin = s*T + k` (matches `SplitAwareSparseNeighborIndexer`).
- Held-out split: hold out a subset of STATIONS for validation (matches
  `evaluate_gridded_wind_heldout`). `allowed_indices` = observed train-station
  linear indices, so held-out tuples are never read as neighbors.

## Training (mirror upstream ffag_polsparse_train.py where it matters)

- Model `FieldFormerCoordinateQuery(d_model, nhead, layers, d_ff, out_dim=2)`;
  defaults match `load_fieldformer_checkpoint` (d_model=128, nhead=4, layers=3,
  d_ff=256) so the checkpoint loads with loader defaults.
- Query path = `forward_observed(q_lin, obs_coords, obs_vals, nb_idx)` where
  `nb_idx = indexer.gather_observed_neighbors(q_lin, exclude_self=True)` and the
  indexer's `allowed_indices` are the train tuples.
- Loss: supervised regression on train tuples (Huber/SmoothL1 or MSE, following
  upstream). Upstream scalar-field physics regularizers (sponge/radiation) are
  NOT transferred to wind unless justified (opt-in flag, off by default).
- Optimizer / lr / weight decay / scheduler / EMA: follow upstream
  (AdamW + EMA is the upstream pattern; loader prefers `ema_model_state_dict`).
- Epochs ~300 (sister-repo scale) with EARLY STOPPING on held-out vector RMSE
  (patience, min-delta). Seeded (torch + numpy). Deterministic data prep.

## Checkpointing (persistent, resumable)

- `checkpoints/` at repo root (already gitignored via `*.pt`). Save a dict:
  `model_state_dict`, `ema_model_state_dict`, `config`, `epoch`, `best_val_rmse`,
  and full provenance (seed, data hashes, normalization/domain_bounds,
  `out_dim=2`, `k_neighbors`/`time_radius`, EMA flag, device/dtype, reproducibility
  command). Write `best` (lowest val RMSE) and `last` checkpoints; `--resume`
  continues from `last`.
- Loadable by `load_fieldformer_checkpoint(out_dim=2)` /
  `build_fieldformer_wind_imputer(checkpoint_path=...)`.
- Final held-out validation report JSON: FieldFormer vs kernel vs city-mean on the
  SAME held-out split via `evaluate_gridded_wind_heldout`. Kept as an artifact; the
  default-imputer switch is deferred (only adopt FieldFormer if it beats the
  kernel on held-out error).
