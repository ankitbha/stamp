# Task 9 Execution Plan: Merge recommendation system

## Objective

Turn the coefficient-level identifiability diagnostics (Task 7) into deterministic
**conservative source report groups**, without silently replacing the
fine-resolution fit (Task 8) or claiming the globally finest identifiable
partition. Build the source ambiguity graph from eligible cross-source
coefficient-pair ambiguities, take deterministically ordered connected
components, retain each edge's triggering coefficient pair and diagnostic values,
flag weak coefficients independently, and emit a global unresolved warning when
the response is rank deficient but no eligible pair defines an edge. Report group
activity and sensor contributions as sums of member sources.

## Context (verified against paper/5.theory.tex subsec:source_merging)

- Source ambiguity graph `E_src = {(k,k') : exists b,b' with ((k,b),(k',b')) in A}`
  (eq. source_ambiguity_graph). Each edge keeps max eligible coherence, min ray
  distance, and the source--basis pair attaining the trigger.
- Deterministically ordered connected components `G = {G_1..G_M}` are the
  recommended report groups. Weak coefficients stay separate flags and create no
  edges. Rank deficiency with no eligible edge -> global unresolved warning, not
  an invented merge.
- Transitive over-merging is explicit: edges A-B and B-C put `{A,B,C}` in one
  component even when A and C are pairwise distinguishable; both trigger edges are
  retained so this is inspectable. Components are `is_conservative`, never a
  finest-partition claim.
- Group reporting (eq. grouped_reports): `theta_{G_a}(t) = sum_{k in G_a} theta_k(t)`
  and `Y_{G_a} = sum_{k in G_a} sum_b h_kb^lag c_kb`. The coefficient fit is NOT
  replaced by a grouped refit; matrix diagnostics remain coefficient level.

Task 7 `DiagnosticsResult` already supplies: `ambiguous_pairs` (each with original
column indices `i,j`, `coherence`, `ray_distance`, `source_i/j`, `basis_i/j` --
eligible pairs with `rho > tau_rho`), `weak_set`, `per_source_weak`,
`numerical_rank`, `reduced_to_original`, and full `column_index`. Task 8
`FitResult` supplies `c_hat` (full, exact zeros on masked), `theta`,
`source_contribution_summaries`, `original_to_reduced`, and
`summarize_report_groups(result, groups)`.

## Design -- new `model/iasa/merge.py`

### Result dataclass `MergeResult`
`report_components` (list of `{members:[source_index], member_names, is_conservative:True}`),
`source_edges` (list of `{sources:(k,k'), source_names, max_coherence,
min_ray_distance, trigger:{col_i,col_j,source_i,basis_i,source_j,basis_j,
coherence,ray_distance}}`), `weak_flags` (per-source, from diagnostics),
`global_unresolved_warning` (bool) + `warnings`, `source_level_activity_summaries`
(from fit, or None), `grouped_activity` (per component, from
`summarize_report_groups`, or None), `grouped_sensor_contribution` (per component
tensor `[N]`, or None), `resolution` metadata (`conservative_connected_components`,
`finest_guarantee=False`), `config`, `metadata`. `to_json_summary()` (tensors ->
lists via `to_numpy`).

### Core entry point
`recommend_merges(diagnostics, *, fit=None, H_tilde=None, config=None) -> MergeResult`.
Steps (pure torch/py; deterministic):
1. Vertices = sorted distinct `source_index` over `diagnostics.column_index`, with
   names.
2. For each `ambiguous_pair`, map `i,j` -> source indices via `column_index`; skip
   same-source pairs. For each unordered source pair keep the coefficient pair
   with **max coherence** (equivalently min ray distance, since
   `d=sqrt(1-rho^2)` is monotone) as the trigger; store max coherence, min ray
   distance, trigger source/basis metadata.
3. Deterministic connected components via union-find over sorted edges; components
   ordered by min source index, members sorted. Mark `is_conservative=True`.
4. Weak flags per source from `diagnostics.per_source_weak`/`weak_set` (weak
   sources never create edges -- guaranteed because `ambiguous_pairs` are eligible
   only).
5. `global_unresolved_warning = (numerical_rank < len(reduced_to_original)) and
   (no source edges)`.
6. If `fit` given: `source_level_activity_summaries = fit.source_contribution_summaries`;
   `grouped_activity = summarize_report_groups(fit, component_members)`. If `fit`
   and `H_tilde` given: `grouped_sensor_contribution[G] = H_tilde[:, member_cols]
   @ c_hat[member_cols]` (full-index columns; masked coeffs are exact zero, so
   harmless). No grouped refit.

### Config
`MergeConfig()` reserved for future `tau_rho_ref` refinement acceptance; Task 9
consumes the ambiguity set exactly as Task 7 produced it, so no threshold is
re-applied here. Deterministic for identical tensors and metadata.

## Sanity Gate S5 (`scripts/run_iasa_sanity.py --gate merge`)
- `duplicate_case`: two identical-fingerprint sources + a distinct third. One
  merge component containing exactly the duplicate pair; edge carries its trigger
  coefficient pair and diagnostic values (`coherence >= 0.999`, ray `~0`).
- `separated_case`: near-orthogonal sources -> every component is a singleton
  (`separated_sources_merged == false`).
- `weak_case`: a near-zero source -> flagged weak, no edge, own singleton
  (`weak_source_flagged == true`).
- Grouped activity and sensor-contribution sums match the true merged total in
  the noiseless duplicate case without a grouped refit
  (`merged_duplicate_total_error <= 1e-4`).
- `is_conservative == true` on every component; `finest_guarantee == false`.
- A `A-B-C` chain -> one component `{A,B,C}`, both trigger edges retained.

## Sanity Gate S6 (`scripts/run_iasa_sanity.py --gate end_to_end`)
Minimal end-to-end IASA run on a **response-builder-derived** `H_tilde` (closes
the gap that S4 only used hand-built matrices): build toy sources, choose
synthetic wind, build `H_lag`, build `Q` and project, generate synthetic `Y` from
known coefficients plus background, run diagnostics, fit, recommend merges, and
emit a summary. Verify:
- The full pipeline runs from public APIs in one call.
- Well-conditioned (separated sources, diverse wind) case recovers coefficients.
- Duplicate-source case recommends a merge with a stable merged contribution.
- Summary includes source/basis names, `c_true`, `c_hat`, coefficient error,
  residual norm, `sigma_J`, numerical/effective rank, condition status, weak set,
  eligible coherence/ray distance, report components, trigger pairs, solver
  convergence, device, dtype, and response boundary metadata.
- Artifacts (if any) go to scratch/logs, not tracked source paths.

Wire `--gate merge` and `--gate end_to_end` into the CLI and `--gate all`; drop
`merge` from `skipped_gates`. (Gate S7 adequacy calibration study remains a
separate pre-Task-10 step.)

## Risks
- Trigger selection must be deterministic when several coefficient pairs tie on
  coherence; break ties by (col_i, col_j) order.
- Component ordering and member ordering must be fully sorted for determinism.
- Grouped sensor contribution must be a pure sum of member columns, never a
  refit; verify it equals the member-column reconstruction exactly.
- The global unresolved warning must fire only when rank deficient AND edge-free,
  not whenever weak coefficients exist.
