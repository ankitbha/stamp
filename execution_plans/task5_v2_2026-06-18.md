# Task 5 Plan v2: Wind Sampler And Exact Open-Boundary Semantics

## Summary

Revise Task 5 so the wind API supports future spatially varying fields, mass accounting is defined per release kernel, directional sanity checks use impulses/positive ages, and boundary/substep semantics are exact.

## API Revisions

- Add `WindSampler.sample(t_index_or_float, position_xy) -> [Vx,Vy]`.
- Adapt current city-level `WindSequence` through `CityWindSampler` rather than making `[T]` arrays the permanent API boundary.
- Keep downstream response/diagnostic/fitting interfaces unchanged when spatial wind arrives later.

## Exact Semantics

- Grid cell centers are integer coordinates; physical extents are `[-0.5,Nx-0.5] x [-0.5,Ny-0.5]`.
- A puff exits only after leaving those physical extents.
- Use fractional final substeps so integration lands exactly at observation time.
- Define retained/dropped mass per release kernel or `(source,basis,tau,t)`, never from sums of repeated `H_lag` observations.
- Track release exit loss separately from Gaussian boundary/truncation loss.

## Revised Gate S1

- Add a required interior source as the matched boundary-loss control.
- Use impulse bases and positive-age slices for directional arrival assertions; keep a constant basis for shape/metadata coverage.
- Add eastward, northward, and two-direction wind cases.
- Add isotropic, anisotropic, and matched boundary-loss cases.
- Add explicit `--strict-all`; non-strict `--gate all` runs implemented gates and reports later gates as skipped.

## Tests

- Test city and position-dependent wind samplers, fractional substeps, physical exit extents, no wrap/reflection, per-kernel mass summaries, anisotropy, optional lag trimming, and validation errors.

## Assumptions

- Task 5 remains sensor-space response construction only.
- Projection, diagnostics, fitting, and merge gates remain later tasks.
