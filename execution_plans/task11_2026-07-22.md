# Task 11 — Evaluation and Reporting (execution plan, 2026-07-22)

## Objective (from roadmap §Task 11 + paper 8.evaluation.tex)
Turn the saved Task-10 runs (`evaluation/iasa_pol/runs/*/result.json` + `arrays.npz`)
into per-experiment and observed-New-Delhi report tables that match the paper's
"Results pending" subsections. Human-readable (markdown + CSV) and machine-readable
(JSON). No new science — a faithful reporting layer over committed results.

## Layers touched
- **New `model/iasa/reporting.py`** — pure functions: `result dict -> ReportTable`
  (title, label, ordered columns, rows, notes). One builder per experiment family
  + observed builders. No I/O, fully unit-testable.
- **New `evaluation/eval_pol_iasa.py`** — CLI: load a runs dir (single run or many),
  dispatch to reporting builders, write `reports/<label>.{csv,md}` + a combined
  `reports/report.json` and `reports/report.md`.
- **`tests/test_iasa_reporting.py`** — unit tests on committed runs + synthetic
  edge cases (A–B–C chain edge retention; weak-pair null; single vs aggregate).
- **`scripts/run_iasa_sanity.py`** — add `--gate reporting` (build tables from the
  committed runs if present, else a reduced live run; assert acceptance checks),
  wire into `--gate all --strict-all`.

## Per-experiment column maps (paper 8.evaluation.tex → result.json fields)
- **exp01** (§results_h1): noise_frac, geometry, sigma_J, numerical_rank,
  effective_rank, condition_number, coefficient_relative_error, (activity error n/a),
  residual_norm, min_visibility. Rows = `result["rows"]`.
- **exp02** (§results_h2): source pair, triggering_pair, max_eligible_coherence,
  ray distance (null when weak/ineligible), individual_relative_error,
  grouped_relative_error, merged, connected component. Chain retains every edge.
- **exp03** (§results_h3): background_mode, requested/effective rank, dependent cols,
  min_visibility, max_absorption, sigma_J, coefficient_relative_error, residual_norm,
  declared_before_fit (predeclared basis id).
- **exp04** (§results_h4): wind_provider × layout → sigma_J, numerical_rank,
  effective_rank, condition, max_eligible_coherence, min ray distance, weak set,
  report groups, coefficient_relative_error. Second table = wind-window ensemble
  quantiles (`wind_window_ensemble.{historical,simulated}`).
- **exp05** (§results_h5a): perturbation_kind, perturbation_value, operator_error_norm,
  sigma_J, coefficient_relative_error, residual_norm (+ structural block row).
- **exp06** (§results_h5b): scenario, diagnostics, fitted activities, grouped
  contributions; rows are robustness scenarios (labelled, NOT intervals).
- **exp07** (§results_lag_selection): lag_window_steps, adjacent_delta (conv ratio),
  sigma_J, numerical/effective rank, n_report_components, selected lag, tau_L,
  selection_criterion, row_count_fixed, coefficients_used_for_selection.
- **exp08** (§results_missing_source): case (null/residual_visible/aligned),
  out_of_span_fraction, calibrated noise, alpha, n_replicates, rejection rates,
  background_rank; + the fixed interpretation note (rejection ⇒ inadequacy w/o cause;
  non-rejection ⇏ completeness).
- **exp09** (§results_temporal_basis): source, basis name(s), coefficient_relative_error,
  activity_relative_error, noise_frac, weak flags.
- **exp10** (§results_footprints): footprint_localization_error_cells,
  footprint_mass_fraction_within_radius, localization_radius_cells, n_active_cells,
  contribution_sum_error, footprints_nonnegative, report_components.
- **observed** (windowed weeks 1–4, Tier 0): 4 tables, one row per week:
  1. Identifiability & report groups: sigma_J, numerical/effective rank, condition,
     max_eligible_coherence, weak_set, report_components.
  2. Proxy apportionment: sensor-signal shares per group + denominator string;
     mark fixed-zero (non-admissible) components unsupported.
  3. Sensor fit & residual diagnostics: n_observed_rows, mask fraction, residual_norm,
     projected_residual_norm, wind_provider, calibration_status (uncalibrated).
  4. Per-monitor group contributions (per week).
  Wind-imputation validation table: from `checkpoints/*wind*.report.json` if present,
  else marked unavailable (kernel imputer, per F1 reconciliation).

## Cross-cutting rules (paper + acceptance checks)
- Undefined weak-pair metrics serialize as JSON `null`, never NaN/"nan".
- Grouped metrics emitted whenever a non-singleton report component exists.
- A–B–C chain: retain BOTH trigger edges in the aggregate (no edge dedup).
- Percentages only as fraction-of-fitted-sensor-signal, with explicit denominator.
- Never serialize an adequacy pass for an uncalibrated run (observed ⇒ status only).
- Aggregation over multiple runs of one experiment = row concatenation with a
  `run` provenance column (seeds/configs stay distinguishable).

## Acceptance checks (mirror roadmap)
single-run report; multi-run aggregate; grouped metrics on non-singleton components;
observed apportionment without ground truth; per-sensor contribution + footprint
tables; weak-pair nulls preserved; A–B–C chain keeps both edges; omitted-source
interpretation text present.
